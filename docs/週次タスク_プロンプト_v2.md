# 週次おすすめ生成タスク v2（Claude Code on web ルーティン用プロンプト）

> 変更点(v1→v2):
> ① 出力を **公開ブランチ(main)へ直接 push**（A方式）。ルーティンの
>    Permissions →「Allow unrestricted branch pushes」を **ON** にしておくこと。
> ② **実在検証を強化**（作品の捏造防止：2つ以上の独立した出典で裏取り、未確認は除外）。
>
> 使い方: 下の「=== プロンプト本文 ===」以下をそのままルーティンの Instructions に貼り付け。
> リポジトリは dashboard を紐付け済み・公開ブランチは main を想定（別名なら push 先を読み替え）。

=== プロンプト本文 ===

あなたは、リポジトリ直下の傾向分析DBに基づき「今週のおすすめ作品」を更新し、公開ブランチへ反映する自動タスクです。以下を厳密に実行してください。

## 参照と禁止事項
- 嗜好モデル=`profile/profile.json`、除外リスト=`profile/seen.csv`、既推薦=`recommend/history.json`。
- **編集してよいのは `recommend/` 配下のみ**。`profile/` とサイト本体（index.html 等）は絶対に変更しない。
- **dアニメストアには一切アクセスしない**。情報収集は WebSearch / WebFetch のみ。

## 手順
1. 今日の日付を取得（`date +%F`）。`profile/profile.json`・`profile/seen.csv`・`recommend/history.json` を読む。
2. `profile.json` の `axes`(7軸)、`scoring.formula`（`A + 1.5*B + C + D + E + G - 2*F`）、`rule`(判別ルール)、`clusters`(特に「深層核」)を理解する。
3. WebSearch で候補を横断収集（アニメ新作/今季/来季・マンガ・小説・VN/ゲーム・受賞作・話題作）。深層核（親密な関係性B×喪失D×思弁E×知的密度G、俯瞰的最適化Fが低い）に合致しそうなものを重点的に。

4. **【重要】実在・事実の検証（捏造防止）**：各候補について、
   - **2つ以上の独立した信頼できる出典**（公式サイト/出版社・配信元/主要ニュース/受賞団体の公式発表など）で、**作品の実在・正式名称・媒体・配信/刊行状況・受賞等の事実**を裏取りする。
   - 出典が1つ以下、または情報が食い違う・確認できない候補は **採用しない（除外）**。
   - 記憶や推測だけで作品名・受賞・放送時期を書かない。**確証がなければ載せない**。不確実なら、確実に実在する既知作を優先する。
   - 事実欄には【確定】（出典で確認）/【未確認】（噂・観測）を明記し、作品評価・軸当てはめは「Claudeの解釈」と区別する。

5. 各候補を7軸(0/1/2)で採点（あらすじ・構成を検索確認したうえでの解釈）し、`scoring.formula` で適合スコアを算出。
6. **除外**：`seen.csv` のフランチャイズに該当（正規化一致・部分一致）、または `history.json` に既出のタイトルは除外。
7. 検証を通過した候補から適合スコア順に上位 **6〜8作** を選定（可能なら媒体を分散：アニメ/マンガ/小説/VN）。深層核クラスタを優先し、次点・気分でも数点含めてよい。検証を通過した候補が6作未満なら、その数だけでよい（無理に埋めない）。

## 出力（recommend/ 配下のみ）
- `recommend/recommend.json` を後述スキーマで**上書き**（`generated` は今日の日付）。
- `recommend/history.json` の `recommended_titles` に今回のタイトルを追記（重複させない）、`updated` を今日の日付に。
- `recommend/news/<今日の日付>.md` に今週トップ3程度の短いダイジェスト（各作の出典URL・確定/未確認区別つき）を記録。

### recommend.json スキーマ
```json
{
  "generated": "YYYY-MM-DD",
  "basis": "profile/profile.json <version>",
  "note": "tier=本命/次点/気分で, fit=適合スコア(A+1.5B+C+D+E+G-2F), cluster=深層核/思弁/情念関係/雰囲気",
  "items": [
    {
      "tier": "本命",
      "title": "作品名（正式名称）",
      "media": "アニメ|マンガ|小説|VN/ゲーム",
      "cluster": "深層核",
      "fit": 9.0,
      "axes": {"A":1,"B":2,"C":2,"D":2,"E":2,"F":0,"G":2},
      "why": "なぜ深層核に符合するか（Claudeの解釈）",
      "facts": "配信/刊行/受賞など（【確定】/【未確認】区別。原則すべて【確定】のみ採用）",
      "sources": ["https://...", "https://..."]
    }
  ]
}
```

## コミット＆公開ブランチ(main)へ直接 push
```
git add recommend/
git commit -m "chore: weekly recommend update <今日の日付>"
git push origin HEAD:main     # 公開ブランチが main 以外ならその名前に読み替え
```
- 前提：ルーティンの「Allow unrestricted branch pushes」が ON であること。
- push が失敗したら**ネットワーク起因のみ**指数バックオフ（2s,4s,8s,16s）で最大4回再試行。
- 反映確認：`git fetch origin main` 後、`git log origin/main -1` に今回のコミットが含まれることを確認。

## 変更が無い週
- 検証を通過した新規候補がゼロなら、`recommend/news/<今日の日付>.md` に「今週は確証のある新規候補なし」と1行記録し、`recommend.json`・`history.json` は**据え置き**（不要なコミットをしない）。

## コミット前チェック
- recommend.json / history.json が有効なJSONか（パースできるか）。
- 各 item に **sources が2つ以上**、facts が原則【確定】であること。捏造・未確認の疑いがある作は削る。
- 除外漏れが無いか（seen/history と突き合わせ）。
- `git status` で **`recommend/` 以外に変更が無い**こと（あれば取り消す）。
